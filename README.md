# amezo.cgi(use strict 版)設置チュートリアル

DB なし・ファイルだけで動く掲示板 CGI を、Web サーバーに置いて動かすまでの手順です。
最後に「サーバー無しでコマンドラインだけで動作確認する方法」と「困ったとき」の表も付けています。

## 0. 先に知っておくこと

- 掲示板の実体は **スレッド1本 = HTML ファイル1個**です。閲覧者は静的 HTML を読むだけで、CGI が動くのは書き込みのときだけです。
- CGI は書き込みのたびに、板ディレクトリの `index.html` などを **書き換えます**。つまり CGI を動かすユーザーに、板ディレクトリへの**書き込み権限**が必要です。
- スクリプトは Referer(どのページから来たか)から板名を読み取ります。**`$urlbase` と実際の URL が1文字でも違うと「エラー」になります**。一番つまずきやすい所です。
- Perl 5.10 以上が必要です(`//` 演算子を使っています)。

## 1. 用意するもの

| 必要なもの | 内容 |
|---|---|
| Web サーバー | CGI(Perl)が使えるもの。Apache 系のレンタルサーバーが一般的 |
| Perl | サーバーに入っているもの(`/usr/bin/perl` が普通) |
| 転送ツール | FTP / SFTP クライアント(FileZilla など) |
| テキストエディタ | **UTF-8(BOM なし)・改行 LF** で保存できるもの |

## 2. ファイル構成(完成形)

```
(Web 公開ディレクトリ)/
├ amezo.cgi        ← 本体
├ blist.txt        ← 板の定義
├ header.html      ← 各ページ上部の共通HTML(スレ立てフォーム)
├ delpass.txt      ← (任意)管理者の合言葉ハッシュ
├ ng.txt           ← (任意)NGワード
├ .htaccess        ← (任意)CGI設定と秘密ファイルの保護
├ global.mem       ← 自動生成(IPごとのスレ立て時刻)
└ main/            ← 板ディレクトリ(板名と同じ名前)
    ├ index.html   ← 1ページ目(CGI が毎回作り直す)
    ├ index2.html  ← 2ページ目以降用(同上)
    ├ lasttime.txt ← 自動生成
    └ 261012182335.html ← スレッド(自動生成)
```

`amezo.cgi` が置かれたディレクトリが、そのまま作業ディレクトリになります(`chdir($Bin)` のため)。`blist.txt` などは `amezo.cgi` と同じ場所に置きます。

## 3. 手順

### 手順1:amezo.cgi の設定を書き換える

`amezo.cgi` の先頭近くを、自分のサイトに合わせます。

```perl
my $amezo   = '＠あめぞう';           # 板タイトルの後ろに付く文字(空 '' でも可)
my $urlbase = 'http://ame.x0.com/';   # ← 自分のサイトのURL。末尾の / を必ず付ける
my $admin   = 'サポート';             # 管理人名
my $post_interval = 5;                # 同じ板への連続投稿の最短間隔(秒)
```

`$urlbase` のルール:

- **掲示板が `https://` なら `https://` にする**(`http://` のままだと Referer が一致せず、全部「エラー」になります)。
- ドメインもパスも、実際のアドレスと同じにする。`amezo.cgi` を `https://example.com/bbs/amezo.cgi` に置くなら、`$urlbase` は `https://example.com/bbs/` です。
- `www.` の有無は、スクリプト側で無視して比較してくれます。

編集するときは、**UTF-8(BOM なし)・改行 LF** のまま保存してください。CRLF だと1行目の `#!/usr/bin/perl` が壊れて動きません。

### 手順2:板ディレクトリを作る

板名は半角英数字にします(例:`main`)。`amezo.cgi` と同じ階層に作り、中に `index.html` と `index2.html` を置きます。

```
main/index.html     ← 下の「最初のボタン」を書く
main/index2.html    ← 空ファイルでOK
```

この2つは **先に存在している必要があります**。無いと、投稿は保存されても一覧ページが作り直されません。

`main/index.html` には、最初の1回だけ使うボタンを書いておきます。CGI が初めて動いた時点で、この中身は丸ごと上書きされます。

```html
<form method="post" action="../amezo.cgi">
<input type="submit" value="一覧を作る">
</form>
```

### 手順3:blist.txt を作る

1行1板で、`板名,背景色,タイトル` の形式で書きます。

```
main,#ddeedd,テスト板
```

| 書き方 | 意味 |
|---|---|
| `#ddeedd!bg.gif` | `!` の後ろは背景画像 |
| `#003300*` | 色の末尾に `*` を付けると白文字モード |
| タイトル中の `#c#` | カンマの代わり(カンマは区切りに使われるため) |

`blist.txt` に載っていない板名は「板名が不正です」で弾かれます(ホワイトリスト)。

### 手順4:header.html を作る

各ページの上に出る共通部分です。**スレッドを立てるフォーム**をここに書きます。

```html
<form method="post" action="../amezo.cgi">
題名 <input type="text" name="subj" size="30"><br>
投稿者 <input type="text" name="name" size="20">
メール <input type="text" name="mail" size="20"><br>
<textarea name="comm" rows="4" cols="70"></textarea><br>
<input type="submit" value="新規スレッド">
</form>
<form method="post" action="../amezo.cgi">
<input type="submit" value="リロード(一覧を作り直す)">
</form>
```

ポイント:

- `action="../amezo.cgi"` は、板ディレクトリ(`main/`)から見た `amezo.cgi` の位置です。
- フィールド名 `subj`(題名)`name`(投稿者)`mail` `comm`(本文)は変えないでください。
- 板名は送っていません。**Referer から自動で判定**されます。
- 2つ目のフォームは、フィールドが空の POST です。これは「投稿せず一覧だけ作り直す」リロードとして扱われます。

### 手順5:アップロードして権限を設定する

FTP の転送モードは **ASCII(テキスト)か自動**にします。バイナリ転送でも内容は壊れませんが、Windows の改行(CRLF)のまま送ると動きません。

権限(パーミッション)の目安です。

| 対象 | 権限 | 理由 |
|---|---|---|
| `amezo.cgi` | `755`(サーバーによっては `705`) | 実行できる必要がある |
| `main/`(板ディレクトリ) | `755` | CGI がスレッドファイルを作る |
| `main/index.html` `main/index2.html` | `644` | CGI が書き換える |
| `blist.txt` `header.html` | `644` | 読むだけ |
| `amezo.cgi` のあるディレクトリ | `755` | `global.mem` を作る |

CGI が「あなたのユーザー」として動くサーバー(suexec / CGIラッパー方式のレンタルサーバー)なら、上の権限で足ります。
書き込みエラーになる場合のみ、サーバーの説明を確認したうえで `777`(ディレクトリ)/ `666`(ファイル)を試します。他人も書き込めてしまう設定なので、最後の手段です。

### 手順6:.htaccess を置く(Apache の場合)

`amezo.cgi` と同じ場所に置きます。

```apache
Options +ExecCGI
AddHandler cgi-script .cgi

# 秘密ファイルを Web から読めなくする
<FilesMatch "^(delpass\.txt|ng\.txt|global\.mem)$">
    Require all denied
</FilesMatch>
```

- 古い Apache 2.2 なら、`Require all denied` の代わりに `Order allow,deny` と `Deny from all` を書きます。
- レンタルサーバーによっては `Options` や `AddHandler` を書くと 500 エラーになります。すでに CGI が有効な場所なら、最初の2行は不要です。
- 板ディレクトリの中の `lasttime.txt` も見せたくなければ、同様に保護してください。

### 手順7:動作確認

1. ブラウザで `https://(自分のサイト)/amezo.cgi` を開きます。
   **スクリプト自身のソースが文字で表示されれば、CGI は動いています**(GET で呼ぶとソースを出す仕様です)。
   - 500 エラー → 「困ったとき」の表を見てください。
   - ダウンロードが始まる / ソースが HTML として崩れて出る → CGI として実行されていません(手順6や、サーバーのCGI設定を確認)。
2. 板のページ(`https://(自分のサイト)/main/index.html`)を開くと、「一覧を作る」ボタンだけが出ます。押してください。
   - 板のページが表示され、header.html のフォームが出れば成功です。
   - ボタンを押しても「一覧を作る」ボタンのままなら、`index.html` を置いてから5秒以内だったためです(連打対策で作り直しを間引いています)。少し待ってからもう一度押してください。
   - 「エラー」と出たら、`$urlbase` が実際の URL と合っていません(「困ったとき」を参照)。
3. 題名・投稿者・本文を入れて「新規スレッド」を押します。
4. スレッドが一覧に出て、`main/` に `261012182335.html` のようなファイルが増えていれば完了です。
   同じスレッドの返信フォームから、レスも付けてみてください。

## 4. 管理者機能(任意)

### 合言葉を設定する

SSH が使える場合:

```bash
perl -e 'print crypt("あなたの合言葉", q($6$好きな文字列$)), "\n"' > delpass.txt
```

- 合言葉は**半角英数字**にしてください。
- `$6$` と後ろの `$` の間は、ランダムな英数字(最大16文字)にします。例:`q($6$k3Jd9sLq$)`
- `delpass.txt` は `amezo.cgi` と同じ場所に置きます。**手順6の保護を必ず入れてください**。
- ファイルが無い、または空なら、削除機能は誰にも使えません(初期状態)。

### 使い方

**名前欄に合言葉を入れて**投稿すると、管理者操作になります(本文欄の内容で動作が変わります)。

| 操作 | 名前欄 | 本文欄 | 投稿の場所 |
|---|---|---|---|
| スレッドを丸ごと削除 | 合言葉 | **空** | そのスレッドの返信フォーム |
| 特定のレスを削除 | 合言葉 | `3` / `3,5` / `5-8` | そのスレッドの返信フォーム |
| スレッドを下へ沈める | 合言葉 | `p3`(3日ぶん古くする) | 同上 |
| スレッドをロック | 合言葉 | `x` | 同上 |
| 管理人として発言 | 合言葉 | 本文 | メール欄に何か入れる |

- スレッド削除は、ファイルを `x(ID).html` に**改名して権限を 600 にするだけ**です。戻したいときは、FTP で名前を元に戻して権限を 644 にします。
- 削除や沈めた後は、一覧がすぐには更新されません。header.html の「リロード」ボタンを押すか、何か1件投稿すると更新されます。
- ロック(`x`)したスレッドは、権限が 404 になり、CGI から書き込めなくなります。解除は FTP で 644 に戻します。

### NGワード(ng.txt)

1行1ワードで、`ワード,オプション` と書きます。

```
spam,c
荒らし太郎,n
宣伝文句
```

| オプション | 動作 |
|---|---|
| `c` | 本文に含まれたら、投稿を無かったことにする |
| `n` | 名前に含まれたら、投稿を無かったことにする |
| 無し | その文字列だけを全項目から削除して、投稿は通す |

## 5. 掲示板のルール(仕様の一覧)

| 項目 | 内容 |
|---|---|
| 投稿サイズ | 7500 バイトまで |
| 本文 | 改行20回まで |
| 題名 | 20文字まで(空白と `＿` は除去) |
| 名前 | 30文字まで(空白は除去) |
| 連続投稿 | 同じ板で `$post_interval` 秒未満はエラー |
| スレ立て | 同じ IP から **180秒に1回** |
| 二重投稿 | 直前のレスと名前・本文が同じならエラー |
| 一覧 | 更新順(レスが付くと上がる)、1ページ20スレッド |

## 6. サーバー無しで動作確認する(コマンドライン)

SSH やローカルの Linux / macOS で、CGI を直接動かして試せます。

```bash
mkdir -p /tmp/bbs/main && cd /tmp/bbs
cp /path/to/amezo.cgi .
perl -c amezo.cgi                       # 構文チェック。"syntax OK" が出ればよい

echo "main,#ddeedd,テスト板" > blist.txt
echo "<hr>header<hr>" > header.html
: > main/index.html
: > main/index2.html

# 新規スレッドを POST してみる(本文 "name=taro&subj=test&comm=hello")
BODY='name=taro&subj=test&comm=hello'
printf '%s' "$BODY" | env \
  REQUEST_METHOD=POST CONTENT_LENGTH=${#BODY} \
  HTTP_REFERER=http://ame.x0.com/main/ \
  SCRIPT_FILENAME=$PWD/amezo.cgi REMOTE_ADDR=1.2.3.4 \
  perl -w amezo.cgi
```

`Location: http://ame.x0.com/main/` と出れば成功で、`main/` にスレッドファイルと `index.html` ができています。
`$urlbase` を変更している場合は、`HTTP_REFERER` もそれに合わせてください。`-w` を付けているので、警告があれば画面に出ます。

## 7. 困ったとき

| 症状 | 原因と対処 |
|---|---|
| 500 Internal Server Error | ① 権限が `755` か ② 改行が LF か(CRLF だと壊れる) ③ 1行目の Perl のパス(`which perl` で確認) ④ サーバーのエラーログ ⑤ `perl -c amezo.cgi` |
| 「エラー」とだけ出る | **Referer が `$urlbase` と合っていない**。`http`/`https` の違い、ドメイン、パス、末尾 `/` を確認。ブラウザやセキュリティソフトが Referer を送らない設定の場合もある |
| 「不正なリクエストです」 | Origin ヘッダが `$urlbase` と一致していない。多くは `http`/`https` かドメインの違い |
| 「板名が不正です」 | `blist.txt` にその板名が無い、またはフォルダ名と違う |
| 「スレッドを作成できません」 | 板ディレクトリに書き込み権限が無い |
| 投稿はできるが一覧が更新されない | `index.html` / `index2.html` が無い、または書き込めない。直前の更新から `$post_interval` 秒以内の場合もある |
| 文字化け | `amezo.cgi` と各ファイルを **UTF-8(BOM なし)**で保存し直す |
| 「投稿内容が大きすぎます」 | 本文が長すぎる(7500バイトまで) |
| 「あと○秒たってから…」 | スレ立ての間隔制限(IPごとに180秒)。急ぎなら `global.mem` を削除する |
| 管理者操作が効かない | `delpass.txt` が `amezo.cgi` と同じ場所にあるか。合言葉が半角英数字か。ハッシュが `$6$` で始まっているか |

## 8. 使い始める前のチェックリスト

- [ ] `$urlbase` を自分の URL(`https://…/`)に変えた
- [ ] `amezo.cgi` が UTF-8(BOM なし)・LF で、権限 755
- [ ] 板ディレクトリに空の `index.html` と `index2.html` がある
- [ ] `blist.txt` に板が書いてある
- [ ] `header.html` にスレ立てフォームがある(`action="../amezo.cgi"`)
- [ ] `delpass.txt` `ng.txt` `global.mem` を Web から読めないようにした
- [ ] 実際にスレッドを立て、レスを付けられた
