========================================================================
 サポートスクリプト（あめぞう型掲示板） UTF-8 版（patch 適用・use strict 対応）
 https://csmith.jp/amebbs01/
========================================================================

■これは何か

 あめぞう型掲示板「サポートスクリプト（サポスク）」を、
 文字コード UTF-8 で動くように書き直したものです。
 元は Shift_JIS 専用でした。作者は ＠あめぞう(仮) 管理人のサポート氏。

 UTF-8 にすると、こうなります。

  ・「＼」「～」「①②③」「髙」など、Shift_JIS で化けやすい文字が通る
  ・jcode.pl が不要になる（新しい Perl で動かないという問題も消える）
  ・エディタもブラウザも今どきの既定のまま扱える

 この版は、UTF-8 版にセキュリティ・堅牢性のパッチを当て、
 amezo.cgi と dai.cgi を use strict; use warnings; で書き直したものです
 （変更点は「■パッチ・use strict 版での変更点」に書いてあります）。

 必要な環境：Perl 5.10 以上（「//」演算子を使っています）。
 普通の CGI として動かす前提です。mod_perl（ModPerl::Registry）や
 PSGI の上では動かさないでください。

 動作確認について
  ・元の UTF-8 版は、靴屋（https://csmith.jp/）が作成し、エックスサーバー上の
    サブディレクトリで一通り動作確認しています（2026-08-30 / Perl 5.16）。
  ・この版（patch 適用・use strict 対応）は、Perl 5.38 でコマンドラインから
    投稿・返信・管理者操作などを動かして確認したものです。
    レンタルサーバー上での確認は、まだ行っていません。


■同梱ファイル

 amezo.cgi          本体
 dai.cgi            ヘッドライン生成
 blist.txt          板の定義（3板ぶんの雛形）
 header.html        ヘッダ／index.html の雛形
 ng.txt             NGワード（空）
 delpass.txt        削除機能の合言葉ハッシュ（空。設定は後述）
 htaccess/          .htaccess の雛形（後述）
 README.txt         このファイル
 CHANGES.txt        Shift_JIS 版からの変更点の一覧

 文字コードは全て UTF-8（BOMなし）、改行は LF です。
 アップロードは必ずバイナリモード（改行変換なし）で行ってください。

 jcode.pl は不要になったので入っていません。

 dai.cgi は、blist.txt の板を順に読み、各板の index.html から
 ヘッドライン（<!-- HEAD LINE --> と <!-- HEAD LINE END --> の間）を
 取り出して並べるだけのスクリプトです。ブラウザで dai.cgi を開けば
 確認できます。


■設置手順

 1. amezo.cgi と dai.cgi の1行目を、鯖の Perl のパスに合わせる

        #!/usr/bin/perl          ← /usr/local/bin/perl のこともある

    SSH が使えるなら `which perl` で分かります。
    あわせて `perl -c amezo.cgi` と `perl -c dai.cgi` を実行して、
    「syntax OK」と出れば、構文は通っています。

 2. amezo.cgi の冒頭にある設定を書き換える

        my $urlbase = 'http://ame.x0.com/';
          ↓
        my $urlbase = 'https://example.jp/bbs/';

    ・末尾のスラッシュを忘れずに。
    ・サイトが https なら https:// にします。http:// のままだと、
      投稿のたびに「エラー」になります。
    ・URL は amezo.cgi を置いたディレクトリまで書きます。
      www. の有る無しは、スクリプト側で無視して比較します。
    ・書き換えるのは引用符の中だけです。行頭の「my」と行末の「;」は
      消さないでください（use strict なので、消すと動かなくなります）。

    すぐ下の $amezo（掲示板の名前）と $admin（管理人名）も好きに変えて
    ください。同じ場所に、次の設定もあります。

        my $post_interval = 5;

    同じ板への連続投稿の最短間隔（秒）です。この間隔より短い投稿は、
    エラーにして保存しません。0 にすると間隔制限がなくなります。

 3. blist.txt を編集する。1行1板で

        [URL上の板名],[背景色],[日本語名]

    ・板名は blist.txt に載っているものだけが使えます（載っていない板名は
      「板名が不正です」で弾かれます）。
    ・板名の先頭に「.」を付けるとヘッドラインに出ません（隠し板）。
    ・背景色のうしろに「!画像パス」で背景画像になります。
    ・背景色の末尾に「*」を付けると、白文字モードになります。
    ・日本語名の中でカンマを使いたいときは「#c#」と書きます。

 4. blist.txt に書いた板の名前でディレクトリを作る

 5. header.html の板リンクを、自分の板構成に合わせて書き換える

 6. header.html をコピーして、各板ディレクトリに
    index.html と index2.html という名前で置く

    この2つは先に存在している必要があります。無いと、投稿は保存されても
    一覧ページが作り直されません。

 7. .htaccess を置く（htaccess/ の中の雛形を使う）

        htaccess/cgi-htaccess.txt   → CGI を置いたディレクトリに .htaccess として
        htaccess/board-htaccess.txt → 各板ディレクトリに .htaccess として

    これで文字コードの指定、投稿者IPの入った global.mem の遮断、
    「投稿しても画面が更新されない」キャッシュ問題の対策が入ります。

 8. パーミッションを設定する

        amezo.cgi  dai.cgi                     755
        blist.txt  header.html  .htaccess      644
        ng.txt  delpass.txt                    400
        板ディレクトリ                          755
        板の index.html  index2.html           644

 9. ブラウザで  http(s)://～/main/  を開き、
    題名・投稿者・本文を空のまま「新規投稿」ボタンを押す。
    何も書かずに押すと、投稿はされず、一覧だけが作り直されます。
    背景色と板のタイトルが変われば成功です。

    ※ 「リロード」のリンクは、ブラウザで開き直すだけです。
       一覧は作り直されません。

    押しても変わらないときは、index.html を置いてから5秒以内
    だった可能性があります（連打対策で、一覧の作り直しを間引いています）。
    少し待ってから、もう一度押してください。


■最終的な配置

    掲示板のディレクトリ/       (755)
        ├ .htaccess             (644)  ← htaccess/cgi-htaccess.txt
        ├ amezo.cgi             (755)
        ├ dai.cgi               (755)
        ├ blist.txt             (644)
        ├ header.html           (644)
        ├ ng.txt                (400)
        ├ delpass.txt           (400)  ※削除機能の合言葉。初期は空
        ├ global.mem            (600)  ※自動生成
        │
        ├ main/                 (755)
        │   ├ .htaccess         (644)  ← htaccess/board-htaccess.txt
        │   ├ index.html        (644)
        │   ├ index2.html       (644)
        │   ├ lasttime.txt             ※自動生成（板ごとの最終投稿時刻）
        │   └ 261012182335.html        ※スレッド（自動生成）
        ├ zatsu/                (755)
        └ test/                 (755)

 amezo.cgi は、自分のあるディレクトリを作業ディレクトリにして動きます
 （blist.txt や global.mem は amezo.cgi と同じ場所を見ます）。


■NGワード（ng.txt）

 1行1件、カンマ区切りで [NGワード],[オプション] と書きます。

    オプション  意味
    ----------  ------------------------------------------------
    n           投稿者欄専用。一致したら投稿そのものを無効にする
    c           本文欄専用。一致したら投稿そのものを無効にする
    (空)        投稿者・メール・本文から、一致した部分だけを削る

 例）

    あぼーん,
    スパム,n
    荒らし,c

 UTF-8 のままで動きます。
 空行は無視されます。改行が CRLF のファイルでも動きます。


■スレッドの削除（管理人向け）

 合言葉のハッシュは amezo.cgi 本体ではなく、別ファイル delpass.txt に
 置きます。amezo.cgi は GET でソースが見える作りですが、合言葉のハッシュは
 別ファイルにあり、その delpass.txt は .htaccess で web から読めないように
 遮断してあるので、外からは見えません。

 初期状態では delpass.txt は空です。この状態では削除機能は誰も使えません。
 設置者であっても、合言葉を設定するまでは使えません。
 （元の作者のパスワードは削除済みです。ハッシュ方式も、時代遅れの DES を
   やめて SHA-512 crypt に変えてあります）

 手順は2ステップです。

 1. 合言葉のハッシュを作る（サーバ上で実行してください）

       perl -e '@c=("A".."Z","a".."z",0..9,".","/"); $s=join"",map{$c[int(rand(@c))]}1..16; print crypt($ARGV[0], "\$6\$$s\$"), "\n"' "好きな合言葉"

    "好きな合言葉" の部分を自分の合言葉に変えて実行します。
    "$6$……$……" で始まる長い文字列が出るので、それを控えます。
    （$6$ は SHA-512 crypt の目印。salt は毎回ランダムに作られます）

    ※ SHA-512 crypt なので合言葉の長さ制限は実質ありません。
      日本語の合言葉でも構いませんが、半角英数字のほうが無難です。

 2. delpass.txt に、1 で出た文字列を1行だけ書いて保存します。

       $6$abcdefghijklmnop$XXXXXXXX……（1で出た値）

    ファイルには他に何も書かないでください。
    パーミッションは 400 または 600 にしておきます。

 これで合言葉が有効になります。

 使い方は、投稿フォームの「投稿者」欄に合言葉（ハッシュではなく
 元の文字列のほう）を入れ、消したいスレッドへのレスとして送ります。

    ・本文が空          → スレッドを x***.html にリネームして隠す
    ・本文に 3 や 5-8   → その番号のレスを削除（3,5-8 のように複数も可）
    ・本文に p3         → スレッドの更新時刻を3日ぶん過去にして、下へ沈める
    ・本文に x          → スレッドファイルを書き込めなくする（ロック）
    ・メール欄に何か入れる → 削除ではなく管理人名で発言する

 ・数字・p・x は組み合わせられます（例：「3,p2」）。
 ・メール欄が「@」を含まない場合、そのメールは捨てられます。
 ・スレッドを隠したとき（x***.html）は、FTP などで名前を元に戻して
   権限を 644 にすれば復活します。ロックしたスレッド（権限 404）も、
   権限を 644 に戻せば解除できます。
 ・削除や沈める操作のあとは、一覧がすぐには更新されません。
   題名・投稿者・本文を空のまま「新規投稿」を押すか、何か1件投稿すると
   更新されます。

 ※合言葉を変えたくなったら、1・2 をやり直して delpass.txt を
   書き換えるだけです。amezo.cgi を触る必要はありません。


■動かないときは

 症状                          だいたいの原因
 ----------------------------  ------------------------------------------
 Internal Server Error (500)   1行目の Perl パスが違う／改行が CRLF に
                               なっている／amezo.cgi が 755 でない／
                               Perl が 5.10 より古い（「//」で構文エラー）。
                               `perl -c amezo.cgi` で確かめる
 「エラー」とだけ出る          $urlbase と実際の URL が食い違っている
                               （http と https の違い、ドメイン、パス、末尾の
                               スラッシュ）。ブラウザが Referer を送って
                               いない場合も
 「不正なリクエストです」      Origin ヘッダが $urlbase と食い違っている。
                               多くは http と https の違い
 「板名が不正です」            blist.txt に、その板名が載っていない
 「スレッドを作成できません」  板ディレクトリが 755 でない（CGI が書けない）
 「連投を検知しました」        同じ板への投稿が $post_interval 秒より近い。
                               少し待ってから投稿する
 「あと○秒たってから…」      同じ IP からの新規スレッドは180秒に1回
 一覧が更新されない            板ディレクトリが 755 でない／
                               index.html が 644 でない（CGIが書けない）／
                               index.html、index2.html が無い／
                               直前の更新から5秒以内
 投稿すると文字化けする        ファイルを Shift_JIS で保存してしまった。
                               UTF-8（BOMなし）で保存し直す
 画面が古いまま               板ディレクトリに .htaccess
                               （board-htaccess.txt）を置いていない

 amezo.cgi と dai.cgi は use warnings で動いています。普通に使っていれば
 警告は出ませんが、出た場合はサーバーのエラーログに書かれます
 （画面には出ません）。原因調査のときは、エラーログを見てください。


■パッチ・use strict 版での変更点

 UTF-8 版からの主な変更です（Shift_JIS 版からの変更は CHANGES.txt を
 見てください）。

 [use strict]
  ・amezo.cgi と dai.cgi を use strict; use warnings; で書き直した。
    変数は my で宣言し、関数同士で共有する変数はファイルの先頭で宣言した。
  ・ファイルハンドルを my $fh 形式にし、flock の数値を LOCK_EX などの定数に
    した。
  ・動作は変えていない。ただし次の点だけ変わっている。
      - 二重カキコの判定時に、フォーム行を書き戻す処理をやめた
        （同じ内容を同じ位置に書き直すだけだったので、結果は同じ）。
      - 管理者操作（del）の「メール欄」「本文欄」の空判定を、「0」を
        入力しても空扱いにならないようにした。
      - 管理者操作で、残ったレスから日付が取れなかったときは、スレッドの
        元の更新時刻を使う。
      - dai.cgi：blist.txt の色の末尾の「*」と、タイトルの「#c#」を処理する
        ようにした。index.html が無い板でも落ちない。

 [パッチ]
  ・amezo.cgi の作業ディレクトリを、スクリプトのある場所に固定した
    （dai.cgi も同じ）。実行場所に左右されない。
  ・CONTENT_LENGTH を、読み込む前に検査する。
  ・$urlbase の比較で、「.」などの記号を普通の文字として扱う（\Q..\E）。
    設定側の www. も外して比較する。
  ・板名は blist.txt に載っているものだけを許す（ホワイトリスト）。
  ・スレッド番号は数字だけを許す（../ などのパス操作を防ぐ）。
  ・名前・本文・題名の「0」が、未入力扱いにならないようにした。
  ・ng.txt の空行や CRLF で、NGワード処理が壊れないようにした。
  ・新規スレッドの作成を sysopen の O_EXCL で行い、同じ秒に立てても
    上書きされないようにした（ID が使用済みなら1つ進める）。
  ・見えない文字（ゼロ幅・双方向制御など）を除去し、見た目が同じ管理人名の
    偽装を防ぐ。
  ・連続投稿は、エラーにして保存しない。空の投稿（一覧の作り直し）だけ、
    間引く（$post_interval）。
  ・一覧の並び順を、桁数を揃えた更新時刻で決める（sprintf）。
  ・スレッドを読む処理（res）で、ファイルが無いときのエラーと、
    開始番号（from）が数字かどうかの検査を追加した。
  ・スレッドファイルに meta charset と viewport を付けた。

 ※これらの変更は、CHANGES.txt にも追記してください。


■そのまま公開する前に

 このスクリプトは 1999〜2003 年に書かれたものが元です。
 この版では XSS 対策を強化しました（投稿内容を & " < > ' すべて
 HTMLエスケープ、自動リンクは https?: 限定で rel 付き、folder の
 パストラバーサル禁止。詳細は CHANGES.txt [13]）。素朴なスクリプト
 埋め込みや属性インジェクションは防げます。CSRF も、referer チェックに
 加えて Origin ヘッダ検証を入れ、他サイトからの投稿を弾きます
 （CHANGES.txt [17]）。

 スパム対策は「同一IPから180秒は新規スレッド不可」「同じ板への連続投稿は
 $post_interval 秒（初期値5秒）以内ならエラー」「NGワード」だけで、
 今のボットには通用しません。
 公開して運用するなら、少なくとも

  ・投稿フォームに CAPTCHA を入れる（Cloudflare Turnstile など）
  ・Cloudflare などのレート制限を前段に置く
  ・ng.txt に URL のパターンを仕込む

 くらいはしてください。
